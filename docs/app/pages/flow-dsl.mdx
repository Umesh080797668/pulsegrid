# Flow DSL (JSON stored in PostgreSQL)

Below is a canonical Flow DSL JSON example (copied from the blueprint):

```json
{
  "id": "flow_abc123",
  "name": "New Shopify Order → Fulfilment",
  "trigger": {
    "connector": "shopify",
    "event": "order.created",
    "filters": [{ "field": "order.total_price", "op": "gt", "value": "0" }]
  },
  "steps": [
    {
      "id": "step_1",
      "type": "action",
      "connector": "airtable",
      "action": "create_record",
      "input": { "table": "Orders", "fields": { "OrderID": "{{trigger.id}}", "Total": "{{trigger.total_price}}" } }
    },
    {
      "id": "step_2",
      "type": "action",
      "connector": "slack",
      "action": "send_message",
      "input": { "channel": "#fulfilment", "text": "New order {{trigger.id}} for ${{trigger.total_price}}" },
      "depends_on": ["step_1"]
    }
  ],
  "error_policy": { "retry_count": 3, "retry_delay_seconds": 30, "on_failure": "notify_owner" }
}
```

Use this as the canonical example for authoring Flow DSL definitions.

## Authoring Guidelines

- Keep triggers and steps small and well-scoped.
- Prefer idempotent actions and include `idempotency_key` where connector supports it.
- Use `depends_on` to express ordering when steps must wait for previous outputs.

## Versioning and Rollbacks

- Each persisted Flow has versions. Use the API to list versions and rollback when necessary.
- When making breaking changes, create a new version and test in `staging` before promoting to `production`.

## Common Patterns

- Data mapping: use template expressions like `{{trigger.field}}` to copy values from previous steps.
- Error handling: use `error_policy` to control retries and owner notification.

## Validation

Flow definitions should be validated server-side before saving. Validation checks include:

- Required fields present (`id`, `name`, `trigger`, `steps`).
- Step references (`depends_on`) reference existing step ids.
- Input template expressions reference available variables (`trigger`, `steps.*`).

The UI and server will reject malformed DSL JSON and return helpful diagnostics.
